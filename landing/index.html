The Problem

Server Overload

Most real-time solutions open a separate connection for every browser tab. 10 tabs = 10x server load. Pravah fixes this with Leader Election, ensuring only one connection per browser.

Data Leaks

Sending sensitive data over web-sockets or SSE is risky. Pravah uses a Signal-Only Policy—sending only IDs, forcing clients to use authorized REST APIs for actual data.

Getting Started

You can self-host Pravah using Docker in seconds. It runs on a high-performance Go Engine with a minimal footprint.

# Clone and run
git clone https://github.com/sampledge-sse/pravah
cd pravah
docker-compose up -d

Proxying /pravah

To avoid CORS issues and simplify frontend integration, you should proxy the /pravah endpoint from your main domain.

location /pravah {
    proxy_pass http://localhost:3000/pravah;
    proxy_set_header Connection '';
    proxy_http_version 1.1;
    chunked_transfer_encoding off;
    proxy_buffering off;
    proxy_cache off;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
yourdomain.com {
    reverse_proxy /pravah/* localhost:3000 {
        header_up Host {host}
        header_up X-Real-IP {remote}
        # SSE optimization
        flush_interval -1
    }
}
<Location "/pravah">
    ProxyPass "http://localhost:3000/pravah"
    ProxyPassReverse "http://localhost:3000/pravah"
    SetEnv force-proxy-request-1.0 1
    SetEnv proxy-nokeepalive 1
    # Disable buffering for SSE
    RequestHeader set Connection ""
</Location>

1. Install **Application Request Routing (ARR)** and **URL Rewrite**.

2. Create a Reverse Proxy rule pointing /pravah to http://localhost:3000/pravah.

3. Ensure **Response Buffering** is disabled in your web.config:

<system.webServer>
    <urlCompression doStaticCompression="false" doDynamicCompression="false" />
</system.webServer>

Why Go?

The core engine is built with Go 1.25 and packaged as a scratch image. This means:

  • Tiny Footprint: Image size is less than 20MB.
  • Hardened Security: No OS, no shell, no vulnerabilities.
  • High Concurrency: Handles thousands of streams using Go Routines efficiently.
